# Candidate Kernel Interface Review

## Static Evidence

The candidate `vmlinux` is K1OM ELF64. Its configuration enables K1OM MIC PCI,
initramfs, modules, networking, and HVC. Its source includes MPSS handling for
the observed `scif_id`, `scif_addr`, `vnet_addr`, `vcons_hdr_addr`,
`virtio_addr`, `ramoops_*`, `p2p_proxy`, `etc_comp`, and `ulimit` inputs.

Two fresh candidate builds had identical `System.map` and `Module.symvers`:

```text
System.map:    631674771d32602354e780209b86f2193ab24f8135056d654b1729f4967834a6
Module.symvers:811db6826857a10a2be4889d525333c0d2cc7caf53f73baeeecac5d3ba988c3f
```

Their image hashes differed. The normalized configs differed only in their
autogenerated timestamp comment; the legacy build also injects generated build
metadata. This is a reproducibility defect, but no kernel export or module CRC
difference was observed.

## Decision

`PARTIALLY_VALIDATED`

The candidate is MPSS 3.5.1 while the host driver and micctrl are 3.4.10, so
it is not an exact-source reproduction. A bounded RAM-only experiment did,
however, validate this candidate kernel with rebuilt 3.5.1 modules through the
MPSS 3.4.10 host's `online` transition. The required correction was to place
modules and their dependency index under the candidate release directory.

Project PID 1, project SSH, and workload smoke tests have not yet been
revalidated on the compatible candidate kernel. The interface remains an
independent compatibility reconstruction, not an MPSS 3.4.10 rebuild.
